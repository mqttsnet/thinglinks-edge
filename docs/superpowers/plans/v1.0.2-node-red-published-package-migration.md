# Node-RED Published Package Migration Implementation Plan

**Target version:** `1.0.2`
**Created:** 2026-09-01

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Make ThingLinks Edge discover, seed, install, verify, and safely migrate to @mqttsnet/thinglinks-edge-nodes@0.0.1 without breaking existing legacy instances.

**Architecture:** The Manager owns one exact, runtime-protected platform-node contract and serves its original npm tarballs through the existing private registry. New instances start in npm mode; existing instances use a journaled migration with a durable file checkpoint, stage the package while raw nodes remain active, cut over by excluding three raw JS basenames, verify real module ownership, and restore legacy bytes/state on failure or Manager restart.

**Tech Stack:** Node.js 22/24, TypeScript, Fastify, better-sqlite3, dockerode, Vue 3, Node-RED 5.0.4, pnpm 10.32.1

**Spec:** [v1.0.2 Node-RED published package migration design](../specs/v1.0.2-node-red-published-package-migration-design.md)

## Global Constraints

- Edge package is exactly @mqttsnet/thinglinks-edge-nodes@0.0.1.
- Common package is exactly @mqttsnet/thinglinks-node-red-common@0.0.1.
- Edge SHA-512 is sha512-NKsIKyUHNyB+xuXNpCrOqzEYbYflEFeXqC/IgjM2/+AzktSTb7+TZFBWHoqp9FjLDX2crpoah6gn8n+Uy32AkA==.
- Common SHA-512 is sha512-T6QN9RlBF0qbvujaAKNY81BjrcIdbqeqFkLfQsGuKHI8UY2cgad9prF8xUC5n4BbHbNJ7ftBmSBkj+IEZvTJWQ==.
- Node-RED runtime verification uses nodered/node-red:5.0.4-24-minimal.
- Common never enters node-red metadata, platform approval, allowList, palette, or inventory.
- Only the exact Edge package is a platform package; do not trust the whole @mqttsnet scope.
- Existing instances default to legacy mode. New instances use npm mode.
- Legacy raw files remain on disk through the first migration release.
- The compatibility image keeps `/app/nodes`, but npm-mode instances never copy or load it.
- A migration journal and checkpoint are durable before the first runtime mutation; no secrets or plaintext environment values enter SQLite, audit, or UI errors.
- All instance write paths share one injected operation gate. The Manager awaits interrupted-migration recovery before opening its listener.
- line-1 is not migrated until an isolated data-copy success and rollback matrix passes and the user separately authorizes that instance operation.
- Flow Library discovery and Community catalogue discovery are separate external gates.
- Every production change follows red-green-refactor and receives an atomic commit.
- Before each task, re-read `git status` and the target-file diff. Preserve concurrent work, especially any existing `apps/manager/scripts/verify-compose.mjs` change; stage only files and hunks owned by that task.
