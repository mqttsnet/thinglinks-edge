# 协议组件与采集控制模板

Edge 使用统一的 ThingLinks 云连接。现场协议节点负责收发设备数据，服务编码、属性编码和命令编码负责与云端物模型关联。用户不需要在每条流程中配置 MQTT 主题、消息头或签名。

## 首批模板

| 协议 | 采集 | 可选控制 |
|---|---|---|
| TCP | LF/CRLF 或定长分帧；JSON/二进制点位解析 | 设备支持约定 JSON 请求/应答时可用；独立配置控制端点 |
| UDP | 独立数据报；JSON/二进制点位解析 | JSON 请求/应答；独立的 Edge 应答端口 |
| HTTP | GET 定时读取或 POST 设备推送 | 向指定设备接口 POST JSON，等待明确执行确认 |
| Modbus-TCP | FC3/FC4、多寄存器、常见整数/浮点字节序 | 暂不提供：当前组件断网超时后可能在恢复时迟到执行写入，生成器已拒绝开启 |
| OPC UA 兼容采集 | 复用 node-red-contrib-opcua 的标量读取或订阅 | 兼容模板保持关闭 |
| OPC UA 安全采集与控制 | 复用 @tier0/opcua-client，支持证书身份与标量点位映射 | 限定命令目标和类型，收到匹配的 Good 写入结果后确认 |
| S7 | 变量表读取，周期或变化上报 | 已验证地址和类型范围内的单点写入，等待 PLC 写入确认 |

Modbus-RTU 尚需受控串口透传。CoAP、BACnet、IEC104 当前为扩展候选，没有用占位模板表示已经支持。网络可达、现场地址、证书、设备权限及真实设备型号仍需现场确认。

内置 Modbus 模板保留采集能力和现成节点包。云控开关及命令映射不可用，生成与配置副本 API 同样拒绝 `downlinkEnabled=true`。此限制只影响新生成的内置模板：已保存快照和已部署用户流程不会自动改写，已经进入旧驱动的请求也不会因此被撤销。已有控制需由用户明确关闭，并重新部署后再验证；不得据此宣称旧流程控制已经修复。

## 配置步骤

1. 在云连接中配置 ThingLinks 分配的网关身份、MQTT 地址和加密参数。
2. 在 ThingLinks 登记子设备并绑定已发布的产品版本。
3. 打开流程模板，按分类、协议或来源筛选，选择内置模板和目标实例。
4. 查看所需组件；未安装的组件先按现有节点审批与安装流程准备。随产品提供离线包不等于已批准、已安装或已加载。已有实例的策略下发可能需要重启，应安排现场窗口。
5. 填写子设备标识。读取云端模型时明确填写子设备的产品标识和绑定版本；选择服务和属性时，界面显示名称，内部保存编码。离线可手填，但不会显示为已校验。
6. 配置设备地址、采集周期和点位。源字段是设备报文路径、寄存器偏移或 PLC 变量地址；属性编码是对应的云端物模型属性。数值上报使用 `原值 × 倍率 + 偏移`。
7. 对已提供控制能力的协议，需要控制时显式开启，并将云端单参数命令映射到目标点位。控制值按相反方向换算；无效类型、越界值或不明确的映射会被拒绝，不会自动截断或限幅。
8. 预览后部署。默认新增流程并保留现有流程；整体替换是独立选择。预览后有人修改实例流程时，需要重新预览。

内置模板可保存为配置副本，副本保留原始组件版本要求。普通自定义流程仍支持从实例或文件保存，用于更复杂的厂商协议和现场逻辑。

## Modbus-TCP 现场接入

Modbus 可以先验证设备，再配置上云身份。选择运行中的实例并准备固定版本组件后，填写设备地址、端口、站号和读取范围，点击“试读一次”。读取由该实例中的现成 Node-RED Modbus 节点执行；页面显示原始寄存器、十六进制和当前点表换算结果。试读不需要云端设备或服务编码，也不向云端上报。

- 地址填写设备可达的 IP 或域名，端口是设备端口，默认 502；不需要给实例新增入站映射。容器中的 `127.0.0.1` 指向实例自身。
- 站号支持 0–255，默认 1。串口转 TCP 网关通常使用 1–247，直连设备是否使用 0 或 255 以设备手册为准。
- FC3 读取保持寄存器，FC4 读取输入寄存器。协议起始地址从 0 开始，单次最多 125 个连续寄存器；一个 32 位点占两个寄存器。不要把寄存器数量当作点位数量。
- 点表可粘贴 Excel 表格或 CSV，列为地址、属性编码、数据类型、倍率、偏移。显式选择“相对偏移”“绝对协议地址”或常见五位手册编号，先预览再替换。手册编号模式按 FC3 的 40001 或 FC4 的 30001 换算；其他厂商编号需先按其手册换成协议地址。
- 绝对地址和手册编号导入会计算连续读取范围。范围内的空隙也会被读取，如果设备不允许跨空洞读取，应拆成多个采集流程；当前每份配置对应一个连续读取块。
- 调整字节序、倍率或偏移后，页面可用上次原始样本重新计算。改变连接或读取范围后，样本标记为旧结果，需要重新试读。试读成功后再配置子设备、服务和属性，预览并部署持续采集。

试读会额外建立一个 TCP 连接，支持 FC3/FC4，只触发一次读取。只允许单连接的设备需先安排已有采集释放连接；试读不是无影响的设备扫描。连接超时和重连间隔可在高级配置调整。

完成、失败或取消后，系统清理本次临时流程；页面刷新只查询状态，不重复读取。未确认清理时会阻止再次试读，提供“重试清理”。Manager 重启后只恢复清理，不重放试读。若实例停止或临时流程被外部改动，可能需要恢复实例后清理；未清理完成时不能保留其数据删除实例，也不能从实例保存流程快照。此限制避免临时读取随快照再次部署。

真实读数只证明这一连接与寄存器配置在当时可用。设备型号、网络故障恢复、持续采集负载和 ThingLinks 云端接收仍需分别验收。Modbus 写入控制继续保持关闭。

## 其他协议的现场配置

TCP、UDP、HTTP、OPC UA 和 S7 配置页面提供按协议区分的接入指引，以及五列 Excel/CSV 点表导入。导入保持设备地址原文，先显示格式错误和预览，再由用户确认替换；设备地址的完整语义校验在保存配置或预览部署时执行。一个模板绑定一台逻辑设备，不会通过来源 IP、端口或变量名称自动推断云端身份。

| 场景 | 接入时先确认 | 点位源地址 |
| --- | --- | --- |
| TCP 设备连接 Edge | 设备使用 Edge 主机的映射端口，页面按所选实例显示 TCP 映射；选择换行或固定字节长度分帧 | JSON 路径如 `data.temperature`，或二进制字节偏移 |
| TCP Edge 连接设备 | 填写设备 IP 与远端服务端口，建立连接后等待设备发来数据；要求查询指令的设备需补充请求节点 | 与设备报文格式一致 |
| UDP 设备推送 | 必须匹配 UDP 入站映射；一个数据报是一帧，不跨报文拼接 | JSON 路径或二进制字节偏移 |
| HTTP 定时读取 | 设备 GET JSON 接口、HTTPS 证书及必要账户配置；读取超时可设，默认 10 秒 | 从返回 JSON 根对象开始的路径 |
| HTTP 设备推送 | 页面显示所选实例实际 `httpNodeRoot` 下的请求路径；另行准备带鉴权/TLS 的设备入口 | 从请求 JSON 根对象开始的路径 |
| OPC UA | 服务器服务地址、实际 NodeId 和类型；根据现场安全要求选择兼容或安全模板 | 如 `ns=2;s=Temperature`，不是变量显示名称 |
| S7 | 设备 IP、Rack/Slot、数据块访问方式与 PUT/GET 权限；请求超时默认 3 秒 | 如 `DB1,REAL0`；含逗号的地址用 Excel 分列或 CSV 双引号包裹 |

监听入口若只绑定 `127.0.0.1`，只能由 Edge 主机本机访问；`0.0.0.0` 是监听范围，设备仍需填写 Edge 现场网卡地址。已有映射只是配置记录，不证明网络已可达。HTTP 管理代理要求登录及操作权限，不能把管理会话或编辑器口令分发给设备，也不能通过放开管理端口来代替受保护的设备入口。

TCP 固定二进制帧会预检点位宽度，避免配置必然截断的数据。OPC UA 只处理约定的标量类型和已确认的数据质量；S7 点位须与组件地址语法及实际返回类型匹配。具体支持范围仍以当前参数预览结果和组件运行验收为准。批量录入不会改变现有云控开关或命令映射。

除 Modbus 外，这些页面的连接提示和点表预览不发起临时试读。部署持续流程后仍需观察真实数据、换算值、设备状态和云端接收；不要把配置检查通过当作现场接入完成。

## 数据与命令的状态

- 上报进入 Edge、MQTT 发布、云端物模型匹配及最终落库是不同阶段。`tl-uplink` 提交成功不表示云端已经持久化。
- 命令记录区分排队、执行中、成功、失败、拒绝和结果未知。连接中断后无法确认是否执行时，不自动重写设备。
- 回执状态只描述 MQTT 发布结果。当前 Cloud 实现尚未把回执按 `mid` 关联更新原下发记录，不能将“回执已发出”显示成“云端原命令状态已更新”。
- 同一设备、服务、命令被多个活跃流程声明时，Edge 拒绝歧义执行。停用流程的声明会在心跳过期后失效。
- 命令历史和去重窗口有上限；被淘汰窗口之前的旧消息保守拒绝，避免重新执行。

## 子设备在线状态

实时上行会触发独立的云端状态同步。Edge 先通过官方拓扑查询确认设备属于当前网关，再合并上报在线状态；云端逐台确认后才视为同步成功。无需手工填写状态 Topic。

- 启动实例后，需要收到新数据才恢复云端在线。UDP、HTTP 推送等事件输入需要设备实际发来报文；旧台账和历史补传不会把设备重新标成在线。
- 确认实例停止、移除，或收到明确离线报告后，同步云端离线。通常下一轮检查在 5 秒内发起，最终以云端响应为准；无法查询实例状态时不会猜测它已停止。
- 新模板按采集来源分别观察协议连接与有效采样，同实例多个流程也独立合并。一条采集连接失效不会覆盖其他健康来源；全部来源不可用才下线。详细规则见 [现场设备状态](field-device-presence.md)。
- S7 变化模式保留周期真实采样，并每 60 秒完整同步。UDP、HTTP 推送默认不因数据静默离线；只有设备固定周期上报时才显式填写静默时限。OPC UA 兼容订阅默认增加每 60 秒的独立健康读取，静止值也能提供恢复所需的新采样；这会增加一个会话，周期可在高级配置调整或设为 0 关闭。关闭后，云连接恢复须等待新的订阅通知。
- 采集流程本身使用独立运行租约。删除流程或与 Manager 失联会使该来源过期；续租不作为设备在线证据。更新 Manager 不会自动改写已部署流程，需用新模板重新部署。
- 多实例来源不完整、归属无法确认、容量达到上限或云端逐台拒绝时，状态保持未确认并在诊断中说明；来源冲突需人工核对，不能把状态请求发出当成成功。

状态请求与设备写入、历史补传分开处理。状态变更使用业务回执确认，避免 MQTT 重连自动重放过期的在线消息。Edge 的归属预校验不替代 Cloud 服务端的授权校验。

## 网络设备的控制约定

TCP/UDP 通用模板使用以下 JSON 格式；TCP 以换行结束，应答需要保留 `requestId`。不符合此格式的厂商私有控制协议，需要专门的适配器或自定义流程。

```json
{"requestId":"由 Edge 分配","cmd":"云端命令编码","params":{"设备源字段":30}}
```

设备完成操作后应答：

```json
{"requestId":"与请求相同","ok":true}
```

HTTP 控制请求按点位源字段构造 JSON，设备需返回 HTTP 200 和确认字段为布尔 true。HTTP 202 表示异步接受，不能证明设备已经执行。设备推送模板只在 Manager 接受有效点位后返回 202；未就绪、超时或拒绝接收时返回 503，并提示设备稍后重试。该确认仍不代表 Cloud 已落库，设备重试也可能产生重复样本。

## OPC UA 控制边界

默认受管实例禁用通用 `exec` 节点，Function 节点也不开放外部模块。兼容采集模板继续关闭控制；安全采集与控制模板使用官方发布的 `@tier0/opcua-client@0.6.0` 节点，Edge 只生成连接配置、验证点位质量、映射数值和对接命令回执。旧的自有单次协议执行器已移出正式源码。

安全模板需要单独批准、安装该固定版本，并准备实例内的证书文件。首批离线种子仍只包含既定的三个协议组件；tier0原包及依赖、匹配运行平台的原生构件需要另行准备。ARM64/musl 场景可使用下文的受信兼容构件镜像；不得把组件包校验通过等同于依赖和原生运行环境均已就绪。

固定 `@tier0/opcua-client@0.6.0` 原发布物含 x64-musl 原生构件，原构件在完整 DER 证书链比较上存在互操作缺陷。Edge 提供独立的 `thinglinks-opcua-native 0.6.0-chain.1` 兼容构件，通过该包已有扩展点加载，不改原 npm 包、版本或 SRI。构件随受信运行镜像放在只读系统目录，不能从实例可写目录替换；保留完整信任链、吊销、应用身份、签名与叶证书身份检查。

使用安全模板前需选择含此构件的运行镜像。当前构建配置覆盖 Linux musl：Node-RED 5.0.4 / Node 24 的 ARM64、x64，以及 Node-RED 5.0.7 / Node 24.20.0 的 ARM64；5.0.7 x64 未纳入此构建配置。普通官方镜像不会自动获得修复。构建、来源校验和选用方法见 [OPC UA 原生兼容构件](../../scripts/opcua-native/README.md)。实际设备型号、固件、证书策略和现场环境仍应逐项验收，不通过关闭证书校验绕过连接失败。

单个匹配目标明确返回 `BadWriteNotSupported` 时，服务器已拒绝该节点的写入，模板将其记录为明确失败。没有目标匹配、结果不完整或未知状态时仍记录结果未知，不会自动重写设备。

模板在交给现成节点前检查命令租约与剩余预算；组件不接受绝对截止时间，因此无法保证取消已经发出的写请求。应答超时可能发生在设备实际写入之后，此时记录为结果未知而不自动重写。物理设备型号、网络故障、账户权限、证书与固件兼容仍需分别验收。已有快照不会被自动改写，重新部署旧控制快照时会显示其来源模板当前的能力限制。

## 开发扩展与验证

分层入口见 [模板扩展说明](../../apps/manager/src/core/flows/templates/README.md)。协议包清单及完整依赖锁说明见 [离线组件说明](../../scripts/protocol-seed/README.md)。

```sh
pnpm check
pnpm build
node --experimental-strip-types scripts/prepare-protocol-seed.mjs --verify-only
node --experimental-strip-types scripts/verify-protocol-components.mjs --keep
# 使用上一条输出的精确 state.json 路径
node --experimental-strip-types scripts/verify-protocol-templates.mjs /path/to/state.json --commands
node --experimental-strip-types scripts/verify-protocol-components.mjs --cleanup /path/to/state.json
```

带 `--commands` 的首批验证器按能力声明执行：Modbus-TCP与兼容OPC UA模板只验证采集，控制明确记录 `unavailable`，不计入控制通过数。tier0安全模板需要单独验证协议与页面行为，不能借用首批脚本的通过结果。验证器仅操作有本轮标签和捕获 ID 的隔离资源。模拟设备测试、物理设备验收、已有实例升级和真实 ThingLinks 云端验收分别记录，不能互相替代。
