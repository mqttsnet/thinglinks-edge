# 协议组件与采集控制模板

Edge 使用统一的 ThingLinks 云连接。现场协议节点负责收发设备数据，服务编码、属性编码和命令编码负责与云端物模型关联。用户不需要在每条流程中配置 MQTT 主题、消息头或签名。

## 首批模板

| 协议 | 采集 | 可选控制 |
|---|---|---|
| TCP | LF/CRLF 或定长分帧；JSON/二进制点位解析 | 设备支持约定 JSON 请求/应答时可用；独立配置控制端点 |
| UDP | 独立数据报；JSON/二进制点位解析 | JSON 请求/应答；独立的 Edge 应答端口 |
| HTTP | GET 定时读取或 POST 设备推送 | 向指定设备接口 POST JSON，等待明确执行确认 |
| Modbus-TCP | FC3/FC4、多寄存器、常见整数/浮点字节序 | 暂不提供：当前组件断网超时后可能在恢复时迟到执行写入，生成器已拒绝开启 |
| OPC UA 兼容采集 | 复用 node-red-contrib-opcua 的标量读取或订阅 | 兼容模板保持关闭 |
| OPC UA 安全采集与控制 | 复用 @tier0/opcua-client，支持证书身份与标量点位映射 | 限定命令目标和类型，收到匹配的 Good 写入结果后确认 |
| S7 | 变量表读取，周期或变化上报 | 已验证地址和类型范围内的单点写入，等待 PLC 写入确认 |

Modbus-RTU 尚需受控串口透传。CoAP、BACnet、IEC104 当前为扩展候选，没有用占位模板表示已经支持。网络可达、现场地址、证书、设备权限及真实设备型号仍需现场确认。

内置 Modbus 模板保留采集能力和现成节点包。云控开关及命令映射不可用，生成与配置副本 API 同样拒绝 `downlinkEnabled=true`。此限制只影响新生成的内置模板：已保存快照和已部署用户流程不会自动改写，已经进入旧驱动的请求也不会因此被撤销。已有控制需由用户明确关闭，并重新部署后再验证；不得据此宣称旧流程控制已经修复。

## 配置步骤

1. 在云连接中配置 ThingLinks 分配的网关身份、MQTT 地址和加密参数。
2. 在 ThingLinks 登记子设备并绑定已发布的产品版本。
3. 打开流程模板，按分类、协议或来源筛选，选择内置模板和目标实例。
4. 查看所需组件；未安装的组件先按现有节点审批与安装流程准备。随产品提供离线包不等于已批准、已安装或已加载。已有实例的策略下发可能需要重启，应安排现场窗口。
5. 填写子设备标识。读取云端模型时明确填写子设备的产品标识和绑定版本；选择服务和属性时，界面显示名称，内部保存编码。离线可手填，但不会显示为已校验。
6. 配置设备地址、采集周期和点位。源字段是设备报文路径、寄存器偏移或 PLC 变量地址；属性编码是对应的云端物模型属性。数值上报使用 `原值 × 倍率 + 偏移`。
7. 对已提供控制能力的协议，需要控制时显式开启，并将云端单参数命令映射到目标点位。控制值按相反方向换算；无效类型、越界值或不明确的映射会被拒绝，不会自动截断或限幅。
8. 预览后部署。默认新增流程并保留现有流程；整体替换是独立选择。预览后有人修改实例流程时，需要重新预览。

内置模板可保存为配置副本，副本保留原始组件版本要求。普通自定义流程仍支持从实例或文件保存，用于更复杂的厂商协议和现场逻辑。

## 数据与命令的状态

- 上报进入 Edge、MQTT 发布、云端物模型匹配及最终落库是不同阶段。`tl-uplink` 提交成功不表示云端已经持久化。
- 命令记录区分排队、执行中、成功、失败、拒绝和结果未知。连接中断后无法确认是否执行时，不自动重写设备。
- 回执状态只描述 MQTT 发布结果。当前 Cloud 实现尚未把回执按 `mid` 关联更新原下发记录，不能将“回执已发出”显示成“云端原命令状态已更新”。
- 同一设备、服务、命令被多个活跃流程声明时，Edge 拒绝歧义执行。停用流程的声明会在心跳过期后失效。
- 命令历史和去重窗口有上限；被淘汰窗口之前的旧消息保守拒绝，避免重新执行。

## 子设备在线状态

实时上行会触发独立的云端状态同步。Edge 先通过官方拓扑查询确认设备属于当前网关，再合并上报在线状态；云端逐台确认后才视为同步成功。无需手工填写状态 Topic。

- 启动实例后，需要收到新数据才恢复云端在线。UDP、HTTP 推送等事件输入需要设备实际发来报文；旧台账和历史补传不会把设备重新标成在线。
- 确认实例停止、移除，或收到明确离线报告后，同步云端离线。通常下一轮检查在 5 秒内发起，最终以云端响应为准；无法查询实例状态时不会猜测它已停止。
- 无新数据不会自动判离线，也不会持续伪造新的心跳时间。现场需要静默超时或特定设备断链判断时，应配置相应的设备状态逻辑。
- 多实例来源不完整、归属无法确认、容量达到上限或云端逐台拒绝时，状态保持未确认并在诊断中说明；来源冲突需人工核对，不能把状态请求发出当成成功。

状态请求与设备写入、历史补传分开处理。状态变更使用业务回执确认，避免 MQTT 重连自动重放过期的在线消息。Edge 的归属预校验不替代 Cloud 服务端的授权校验。

## 网络设备的控制约定

TCP/UDP 通用模板使用以下 JSON 格式；TCP 以换行结束，应答需要保留 `requestId`。不符合此格式的厂商私有控制协议，需要专门的适配器或自定义流程。

```json
{"requestId":"由 Edge 分配","cmd":"云端命令编码","params":{"设备源字段":30}}
```

设备完成操作后应答：

```json
{"requestId":"与请求相同","ok":true}
```

HTTP 控制请求按点位源字段构造 JSON，设备需返回 HTTP 200 和确认字段为布尔 true。HTTP 202 表示异步接受，不能证明设备已经执行。设备推送模板返回的 202 也仅表示解析完成并交给流程处理。

## OPC UA 控制边界

默认受管实例禁用通用 `exec` 节点，Function 节点也不开放外部模块。兼容采集模板继续关闭控制；安全采集与控制模板使用官方发布的 `@tier0/opcua-client@0.6.0` 节点，Edge 只生成连接配置、验证点位质量、映射数值和对接命令回执。旧的自有单次协议执行器已移出正式源码。

安全模板需要单独批准、安装该固定版本，并准备实例内的证书文件。首批离线种子仍只包含既定的三个协议组件；tier0原包及依赖、匹配运行平台的原生构件需要另行准备。ARM64/musl验收使用官方原包及同源构建的独立原生构件，原包一键安装尚未通过；不得把组件包校验通过等同于依赖和原生运行环境均已就绪。

模板在交给现成节点前检查命令租约与剩余预算；组件不接受绝对截止时间，因此无法保证取消已经发出的写请求。应答超时可能发生在设备实际写入之后，此时记录为结果未知而不自动重写。物理设备型号、网络故障、账户权限、证书与固件兼容仍需分别验收。已有快照不会被自动改写，重新部署旧控制快照时会显示其来源模板当前的能力限制。

## 开发扩展与验证

分层入口见 [模板扩展说明](../apps/manager/src/core/flows/templates/README.md)。协议包清单及完整依赖锁说明见 [离线组件说明](../scripts/protocol-seed/README.md)。

```sh
pnpm check
pnpm build
node --experimental-strip-types scripts/prepare-protocol-seed.mjs --verify-only
node --experimental-strip-types scripts/verify-protocol-components.mjs --keep
# 使用上一条输出的精确 state.json 路径
node --experimental-strip-types scripts/verify-protocol-templates.mjs /path/to/state.json --commands
node --experimental-strip-types scripts/verify-protocol-components.mjs --cleanup /path/to/state.json
```

带 `--commands` 的首批验证器按能力声明执行：Modbus-TCP与兼容OPC UA模板只验证采集，控制明确记录 `unavailable`，不计入控制通过数。tier0安全模板有独立的协议及页面验收记录，不能借用首批脚本的通过结果。验证器仅操作有本轮标签和捕获 ID 的隔离资源。模拟设备测试、物理设备验收、已有实例升级和真实 ThingLinks 云端验收分别记录，不能互相替代。
