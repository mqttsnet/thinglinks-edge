# 1.0.1 (2026-08-27)

First public release: multi-instance Node-RED hosting on a single on-site machine,
delivered as one `docker compose up` from a published multi-arch image.

## Added

- **Instance lifecycle** — create, start, stop, delete and credential reset for
  Node-RED instances running as sibling containers, with per-instance data volumes
- **Built-in reverse proxy** — instances are reachable only through the Manager;
  the proxy never rewrites paths (`prefix === rewritePrefix`), verified against
  real Node-RED 5.0.4
- **Passwordless editor entry** — the auth token key is derived from each
  instance's `httpAdminRoot`, which Node-RED namespaces per mount path
- **Three-layer health probes** — container / application / flow, with a combined
  verdict that catches "process alive but not working"
- **Host port allocation** — manual entry plus recommendation, with conflict
  detection against both platform records and the live host
- **Web console** — login with forced first-run password change, instance list and
  operations, health dashboard; served by the Manager itself, mount prefix injected
  at runtime so one image works at `/` and under any sub-path
- **Live log streaming** — an SSE endpoint that follows container output, plus a
  console view with level filtering, keyword search, pause/resume and export.
  Reconnects resume from the last delivered line instead of replaying history
- **Container image and Compose deployment** — Manager and instances both run
  non-root on a read-only root filesystem
- **Restricted Docker endpoint** — the Manager no longer touches the host socket;
  all Docker calls go through a proxy with per-method regex allowlists
- **Users and per-instance authorization** — three roles (`admin` / `operator` /
  `viewer`) plus a per-instance grant matrix at two levels (`view` / `operate`),
  so an operator can be scoped to the instances they actually own. Every route
  declares the action it requires explicitly; `instance:list` is deliberately
  separate from `instance:view` because a list has no single instance to judge
- **Backup and restore** — a backup bundles the Manager database and every
  instance's data directory. The database is captured with SQLite's online backup
  API rather than copied: in WAL mode a plain file copy yields a database that is
  missing committed data and still **opens cleanly**. The bundle records a
  `MASTER_KEY` fingerprint, so restoring onto a host with the wrong key fails
  immediately and says why, instead of producing a system that boots and logs in
  but cannot decrypt a single instance credential. Restore is an offline CLI
  operation — overwriting a database the Manager has open corrupts it
- **Offline buffering and replay** — batches that cannot be shipped are written to
  a segment log and replayed in order once the link returns, with segments
  reclaimed only after a full segment ships. The full policy
  (`drop-oldest` / `drop-newest` / `stop-accepting`) must be configured
  explicitly: there is no correct default when the data is being metered.
  Replay progress lives in the spool directory's own database, so the buffer is
  self-describing and can be moved or inspected on its own
- **Cloud uplink** — device registry, tag definitions, value ingest, uplink and
  replay endpoints, plus a field-device view and edge-side metrics
- **Health trend curves** — sampled at `EDGE_METRICS_INTERVAL_SEC` (0 disables),
  kept **in memory only** — fine-grained 10s x 1h, coarse 5min x 24h. Restarting
  clears the history; that is the price of not writing to the box's SD/eMMC card
  every ten seconds
- **Release notes dialog** — `changelogs/vX.Y.Z.zh-CN.md` ships inside the image
  and is shown once after an upgrade. It is deliberately shown *after*, not
  before: the person performing the upgrade and the person using the system daily
  are usually not the same, and the latter is the audience

## Security

- **Per-instance networks** — instances cannot reach each other. Previously they
  shared one bridge network, where a container could reach another instance's
  editor over plain HTTP, bypassing Manager authentication entirely
- **Hard whitelist on container creation** — privileged mode, host namespaces and
  arbitrary bind mounts are rejected; only platform-managed named volumes may be
  mounted, and instance port 1880 may never be published to the host
- **WebSocket authentication and Origin checks** run in `preHandler`; browsers do
  not apply same-origin policy to WebSockets, so cookies alone are hijackable
- **Startup refuses a missing `MASTER_KEY`** rather than falling back to a default
- The Manager runs without host socket access and without supplementary groups
- **Authorization is enforced per route, not per page** — the console hides
  controls the current user lacks, but every endpoint still checks. Hiding a
  button is a usability affordance, never an access control

## Changed

- **Default listen port is now `19100`** (was `8080`). It is the image's
  `LISTEN_PORT`, its `EXPOSE`, and the port the Compose stack publishes.
  Set `EXTERNAL_URL` accordingly, e.g. `http://192.168.10.20:19100`
- **Published to Docker Hub** as
  [`mqttsnet/thinglinks-edge`](https://hub.docker.com/r/mqttsnet/thinglinks-edge),
  a multi-arch manifest for `linux/amd64` and `linux/arm64`. A site machine no
  longer needs the source tree or a toolchain — only Docker.
  32-bit ARM is not supported and cannot be: the official Node.js 24 images
  publish no 32-bit ARM build, and `better-sqlite3` ships no prebuilt binary for it
- **`docker-compose.yml` is now pull-only.** Building from source moved to
  `docker-compose.build.yml`, layered on top. A file that carries both `build` and
  `image` makes `docker compose pull` ambiguous, and pull is what a site upgrade uses
- **The image declares a `HEALTHCHECK`.** Without one, Portainer, Swarm and
  `depends_on: condition: service_healthy` all treat "the process has not exited"
  as healthy — which is exactly the state a wedged Node process is in
- **`DOCKER_SOCK` is configurable** for rootless Docker, whose socket is not
  under `/var/run`

## Fixed

- Container logs were returned as Docker's raw multiplexed stream, mixing 8-byte
  frame headers into the text and making stdout indistinguishable from stderr
- Instance networks leaked: with the Manager attached as an endpoint, Docker
  refuses to delete the network, and that failure was being swallowed
- Host memory exhaustion was computed as `totalmem - freemem`, which blocked
  instance creation on perfectly healthy machines
