# 实例隔离与编辑器访问

Edge 的隔离单位是 Node-RED 实例。一个实例中的节点共享 Node.js 进程、组件和流程数据；需要互不影响的产线或不同信任来源的流程，应建立不同实例。

## 宿主与实例边界

新建受管实例固定以 `1000:1000` 运行，使用只读根文件系统，裁剪全部 Linux capabilities，并启用 `no-new-privileges`。实例只能挂载自己的受管数据目录到 `/data`，不能通过创建参数加入 Docker socket、宿主系统目录、其他实例目录或宿主 PID/network namespace。实例内部的 root 账号不代表宿主 root；当前运行身份也没有修改系统账号数据库的权限。

每个实例配置 CPU、内存、进程数上限，禁止额外 swap；临时目录与容器日志有容量限制。创建时还会计算已登记实例的资源配额总量，为宿主保留余量。已停止实例仍占登记预算，避免同时启动后超配；需要释放预算时，应确认用途并删除不再使用的实例记录。

这些设置不能替代宿主系统与 Docker 的安全更新，也不约束拥有宿主管理员或 Docker 管理权限的人员在 Edge 之外直接修改容器。

## Docker 执行策略服务

Manager 不直接挂载 Docker socket。`docker-proxy` 运行 `dist/docker-policy-main.js`，在独立网络中接收 Manager 的请求。只有该服务挂载 socket；socket 的只读挂载本身不等于 Docker API 只读授权。

执行策略会核对允许的 API、容器和网络的受管归属、镜像范围、数据目录及创建参数。启动或重启前还会核对实际容器的隔离配置，防止通过旧容器或手工改动的容器绕过创建约束。实例网络不能直接访问策略服务；Manager 需要连接实例网络以提供反代和组件源。

部署时保持 Manager、Docker 策略和网络隔离三个服务来自同一发行版本，并保持数据根、网络前缀、实例镜像范围及设备端口范围一致。策略和网络服务应使用发行包配套的最小 `POLICY_IMAGE`；它只包含两个策略入口及必要的 Node.js 内置依赖，不包含 Manager、Web 控制台、业务数据库或 npm。不要将 `PROXY_IMAGE` 设置为旧的 `wollomatic/socket-proxy`；旧组件没有这套请求体与资源归属校验。主 Compose 文件在未设置策略镜像时暂时回退到 `MANAGER_IMAGE`，仅用于兼容旧现场；新部署和升级必须显式填写 `POLICY_IMAGE`，或分别填写 `PROXY_IMAGE`、`NETWORK_IMAGE`。本地源码构建使用 `docker-compose.build.yml`，它从 `apps/manager/Dockerfile.policy` 生成独立的 `thinglinks-edge-policy:dev`。离线包的 `imageRoles` 显式区分三个角色，并按包内清单校验每个角色的镜像引用。

构建覆盖文件给两个策略服务都配置了构建入口，单独构建任一角色也可从源码生成镜像。两个角色在该覆盖文件中统一使用 `POLICY_IMAGE`，不使用旧的分角色镜像覆盖；启动时继续带构建覆盖文件，或同步主 Compose 的镜像配置。离线包允许旧版三角色共享一个镜像，也允许 Manager 与策略使用两个镜像，但 Docker 策略与网络隔离必须共享同一个策略 Config ID。校验器独立固定 Manager 和策略的 Config ID，再核对包内镜像字节、角色、配置引用；安装器拒绝将包内另一个角色的镜像调换过来。

## 网络保护组件与部署约束

网络保护组件已纳入源码与编排合同；以下说明的是配置边界，不能据此认定某台现场主机已经启用网络防护。最终效果需要在实际 Docker 环境验证宿主访问、实例间访问、设备通信和重启恢复。

`network-isolation` 运行 `dist/network-isolation-main.js`，使用 Docker 宿主网络命名空间，以 root 运行但只增加 `NET_ADMIN` capability，不使用 `privileged`。它只挂载私有 `edge-network-control` 卷，不挂载 Docker socket 或实例数据。业务 Node-RED 实例仍不获得 host 网络或 `NET_ADMIN`。

Docker 策略服务通过该私有卷中的 Unix socket 请求受限的网络保护操作；其独立的 `edge-policy-state` 卷记录尚未完成的网络操作。Manager 和 Node-RED 都不能挂载这两个私有控制/状态卷。生产部署应使用 `POLICY_IMAGE` 指向只包含策略与防火墙入口的最小镜像；它不应复用 Manager 镜像。网络创建前要持久化操作意图，确认资源归属、不可变 ID 和网络保护就绪后才完成发布；不确定状态需要核对恢复，不能直接清掉记录或猜测删除网络。

网络操作还带有由可信数据根和网络前缀生成的部署归属标识。共享 Docker 主机上的不同部署必须使用独立配置和状态卷；更改数据根或网络前缀属于受控迁移，不能靠删掉状态卷或借用另一部署的网络绕过归属校验。

该后端按 IPv4 设计，新实例网络必须固定关闭 IPv6，不允许临时启用双栈绕过 IPv4 规则。镜像中的 `iptables`、`iproute2`、`nftables` 只是工具，不能证明宿主内核和实际网络后端兼容；不支持或保护未就绪时，应拒绝放行新网络，而不是跳过检查。

| 配置 | 含义 |
| --- | --- |
| `PROTECTED_HOST_IPS` | 用逗号分隔的明确 IPv4 地址，补充需要保护的宿主地址；不接受域名或 IPv6 |
| `ALLOWED_HOST_ENDPOINTS` | 精确的宿主服务例外 JSON，默认 `[]`；每项只允许 `address`、数值 `port`、`protocol`（`tcp` 或 `udp`） |
| `NETWORK_HEALTH_PORT` | 网络保护的健康探测端口，默认 `31555`；需避免与管理台、编辑器及保留管理端口冲突 |

例如，确有设备采集需要连接宿主上一个指定的 OPC UA 服务时，可以配置单个例外；下面地址仅为填写格式示例：

```dotenv
PROTECTED_HOST_IPS=192.0.2.10
ALLOWED_HOST_ENDPOINTS=[{"address":"192.0.2.10","port":4840,"protocol":"tcp"}]
NETWORK_HEALTH_PORT=31555
```

不能用通配地址、整个网段或 `all` 协议扩大例外，也不能将 SSH、Docker、Manager、编辑器或网络健康管理端口作为普通设备服务放开。规则配置不是全网目的地址白名单；现场设备网络与外网访问仍需要独立的网络策略。

Docker Desktop 的 Linux 虚拟机并不等于 macOS 原生宿主。Mac 原生网卡地址、可到达原生服务的地址需要由部署方只读核对后明确填写，不能只枚举容器内网卡就声称已覆盖原生宿主。切换 Wi-Fi、VPN、网卡、Docker 网络或宿主地址后必须重新核对并验证；旧地址清单不能自动证明新网络仍受保护。

涉及网络保护的真容器验证会操作 Docker 宿主的受管防火墙规则，随机容器名不能单独保证宿主规则隔离。共享现场主机运行此类验证前，应确认保护范围与部署归属，或使用独立的 Docker 验证环境；不要把普通无特权单元测试和宿主网络验证混为一谈。

## 编辑器登录

控制台创建实例时，需要填写并确认独立的「编辑器口令」；页面和服务端都会检查至少 12 位、UTF-8 编码不超过 72 字节。它与管理台账号口令、宿主系统 root 口令分别管理。

日常使用流程：创建实例并等待服务就绪，在实例列表点击「打开编辑器」，在新浏览器标签页输入该实例口令，验证通过后进入它的独立端口；原控制台标签页保留当前页面。停止的实例需要先启动；验证接口不会替用户自动启动实例。进入编辑器需要同时满足 Manager 登录、实例访问授权和实例密码验证；知道实例密码不会增加 Manager 权限，也不会取得其他实例的访问权。

自动化创建建议显式提供 `editorPassword`。兼容旧接口的省略模式仍会生成随机口令，但不提供免密编辑器入口；旧实例的未知口令应由管理员在维护窗口中重置。Manager 的模板部署和实例启停继续按平台授权矩阵判权，编辑器口令是进入编辑器的附加验证。

验证成功后，Manager 返回一次性的独立入口。实例 token 在服务端短暂保留，通过绑定当前会话、实例和权限的交接票据传到实例自己的浏览器来源，不再写入管理台来源的浏览器存储。交接票据一分钟失效，不能重复兑换。

编辑器解锁当前有效期为 30 分钟，超过期限需返回实例页重新验证；连续验证失败按管理账号和实例限速，重新登录不会清除失败计数。登出、停用账号、修改或重置 Manager 密码、撤销实例授权、改变权限或锁定编辑器时，对应的解锁和实时通道会失效。已握手和正在握手的通道都需要重新核验；其他用户和其他已授权实例的连接不因单实例撤权被一并关闭。会话空闲检查不会因为后台保持 WebSocket 而自动续期。

实例密码重置是独立的管理员权限，普通运维不能通过重置密码绕过验证。管理员重置自己的 Manager 密码与重置实例密码是不同操作。启用全员两步验证后，未完成绑定的 Manager 会话不能访问实例编辑器；实例密码不能代替两步验证。

只读授权不会获得流程写入、部署或双向 WebSocket 权限，因此只读查看不包含可写实时通道。授权人员已部署的定时任务是实例中的运行逻辑；撤销人员的网页会话不会自动停止这些任务，需要另外停止实例或部署停用后的流程。

## 独立端口与现场部署

默认编辑器端口范围为 `19200–19263`，通过 `EDITOR_PORT_MIN` 和 `EDITOR_PORT_MAX` 配置。管理台端口与编辑器端口必须分开。Compose 发布相同的宿主与容器编辑器端口，防火墙也需要放行实际使用的范围。

每个实例代际拥有独立端口。分配记录持久化在 Manager 数据库中，重启 Manager 不会改变。删除后重新创建同名实例也会分配新的来源；旧端口保留，不自动回收，避免将浏览器缓存、token 或 Service Worker 留存的来源交给另一个实例。范围用完时，解锁编辑器会明确报错，需要扩大配置范围并同步调整端口映射及防火墙。扩大范围时保留已有端口；不能仅修改配置把已分配端口移出范围。

请使用 `EXTERNAL_URL` 配置的主机名进入管理台，并保持跳转前后的主机名一致。`localhost`、`127.0.0.1` 和局域网 IP 是不同的 Cookie 主机；在这些地址之间切换会造成重新登录或交接失败。需要多个入口时，只配置明确可信的主来源；不要把任意编辑器来源加入管理台的全局跨源白名单。

使用 HTTPS 反代时，每个编辑器对外端口也必须提供 TLS，并转发到 Manager 的相同后端端口，保留正确的 Host，支持 WebSocket Upgrade。不能把所有编辑器请求统一转到后端 `19100`，也不能依赖 `X-Forwarded-Port` 声称请求来自某个实例。未配置对应 TLS 入口时，HTTPS 管理台的编辑器链接不可用；系统不会回退到管理台同源执行编辑器代码。

实例独立端口仅提供自身编辑器与流程路径，不提供 Manager 管理接口，也不接受其他实例路径。主端口不直接提供编辑器脚本。主端口保留已有协议 HTTP API，但流程返回的页面使用受限 CSP，不获得管理台同源存储权限；依赖 Cookie、浏览器存储或复杂页面集成的 Dashboard 必须单独评估兼容性，不能解除安全限制来强行恢复旧行为。

组件面板另允许读取精确的 `<basePath>/npm/-/catalogue.json` 元数据地址。独立端口上的该请求同样要求当前用户有本实例权限并已解锁编辑器，只返回既有已批准组件目录；不会开放整个 `/npm/`、包体下载或 Manager 用户接口。实例安装组件继续通过容器内部的 registry 地址进行。

## 升级已有部署

升级管理组件不会主动重启已经运行的 Node-RED 实例。旧实例也不会因为 Manager 镜像变更就自动获得新的容器配置。新增网络保护组件涉及宿主网络规则，应在升级维护中单独检查其部署和恢复状态。

Manager 可以恢复 legacy 实例的管理网络连接，以继续读取状态和提供经验证的编辑器访问；这不表示旧实例已经满足新隔离要求。旧实例的启动、重启和口令重置可能被新的运行配置预检拒绝，需要在维护窗口重建后再操作。新实例的门禁验收结果不能直接作为旧实例已完成迁移的证明。

升级前保留加密主密钥，备份 Manager 数据和实例流程，核对新旧镜像及节点包。旧实例下一次启动、重启或其他受策略保护的操作若被拒绝，应根据实际差异安排维护窗口，使用受支持的重建或迁移流程重新创建符合约束的容器，再验证采集、云端上报与控制。不要为通过检查而临时开放 root、特权模式、宿主目录或裸 Docker socket。

更新旧 `.env` 中的镜像项，尤其是 `PROXY_IMAGE` 和 `NETWORK_IMAGE`；离线安装器会拒绝不属于当前包的镜像引用，并同时等待 Manager、Docker 策略和网络隔离三个服务健康。已有账号、实例密码和主密钥不能因升级而被默认值覆盖。恢复数据库会影响实例来源分配，恢复操作也应在维护窗口中完成并核对当前实例与端口记录；不能将私有策略状态卷当作普通临时缓存删除。

`docker compose down -v` 会删除网络控制与策略状态的具名卷，即使 Manager 和实例的 bind 数据目录还在。普通升级不要使用该命令。Manager 的业务备份不包含这两个独立卷；应另外保管网络控制域标识、网络描述和未完成操作记录。恢复时需要与实际 Docker 网络 ID、bridge 和归属重新核对，不能把旧状态直接套到另一台主机或另一代网络。

## 当前边界

- 不同端口隔离浏览器的 origin、localStorage 和实例脚本权限，但同一主机名的 Cookie 命名空间仍共享。反代会剥离管理 Cookie、敏感身份头以及实例响应的 Set-Cookie，并拒绝跨实例浏览器请求；恶意页面仍可能干扰可由脚本修改的共享 Cookie，导致操作失败或需要重新登录。不能将端口隔离描述为 Cookie 完全隔离。
- 不同实例的数据挂载和容器资源有约束；同一实例中的第三方节点仍能读写该实例的可写数据，不能把 Function 或组件批准清单当成节点级沙箱。
- 当前没有对实例数据目录实施硬磁盘配额。日志和临时目录有限额，但流程自行写入 `/data` 仍可能占满共享磁盘，需要容量监控和数据保留策略。
- 当前网络保护的范围是受管实例、宿主与其他实例之间的访问约束及明确的宿主服务例外，并非完整的出站目的地址 ACL；现场设备网与外网访问仍需要额外策略。源码中具备网络组件也不证明已有部署的宿主规则已更新或验证。
- 当前限制控制管理入口与容器能力，不自动撤回已经执行的设备命令，也不停止已部署的业务流程。设备侧授权、命令审计和操作维护窗口仍需单独管理。

验收应分别检查普通采集与控制可用、实例无法操作宿主敏感目录、无法借代理操作非受管资源、撤权实时生效、其他实例持续工作以及重启后限制仍存在。源代码和配置存在不代表实际部署已完成这些验证。
